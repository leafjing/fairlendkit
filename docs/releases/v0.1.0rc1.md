# FairLendKit 0.1.0rc1 release notes

Release type: GitHub prerelease. This release is not published to PyPI.

## Highlights

- Preserves the reviewed Milestone 3 audit engine and Milestone 4 installed CLI
  workflow with canonical JSON, CSV, and HTML reports.
- Adds strict alternative-data source, temporal-leakage, revision, reversal,
  coverage, and reason contracts (AD-0).
- Adds disclosure-controlled aggregate quality evidence with primary and
  complementary suppression and historical-release constraints (AD-1).
- Adds explicit cash-flow, rent, and utility adapters and deterministic typed
  signal profiles using Decimal amount semantics (AD-2).
- Adds disclosure-controlled credit-risk diagnostics with deterministic
  counter bootstrap, reliability gates, and complete trace evidence (AD-3).
- Adds potential proxy-risk screening with fixed development/holdout modeling,
  paired and stratified bootstrap evidence, typed flags, and canonical JSON,
  CSV, and HTML projections (AD-4).

## Scope and safety boundaries

This prerelease contains no real alternative-data dataset, admitted data
artifact, or live retrieval invocation. The separately reviewed retrieval
harness is not part of this release tree. This release does not authorize data
download, admission, promotion, repository storage, or redistribution.

Alternative-data outputs are screening and review evidence only. They do not
provide threshold recommendations, automated feature removal, model decisions,
or causal, discrimination, legal, or compliance conclusions.

## Tag signing and publication controls

The public tag is an annotated, cryptographically signed tag created only from
the independently approved release commit after the merge and post-merge CI
gates pass. The release operator must use an identity already associated with
the project maintainer account and publish its public verification material
before tagging. The exact signer fingerprint or SSH public-key fingerprint is
recorded in the release evidence; an unverified or lightweight tag is rejected.

The preflight must prove that the configured signing key exists locally, that
the tag does not exist locally or remotely, and that the approved release commit
is an ancestor of the current `origin/main`. Tag creation uses Git's forced
signing mode (`git tag -s`) and is followed by `git tag -v` plus an exact target
check before the tag is pushed. GitHub Release creation must use
`--verify-tag` and must target the same immutable tag.

Public tags are never moved or reused. A normal rollback is a revert PR against
the merge commit. If a published prerelease must be withdrawn, mark the GitHub
prerelease as withdrawn and publish a correcting version; do not delete or move
the public tag. Deleting a public tag or release requires separate emergency
authorization and a preserved incident record.

## Reviewed execution sequence

The values in angle brackets are filled from independently reviewed evidence;
no command runs if any exact comparison fails.

```bash
git fetch origin --prune --tags
test "$(git rev-parse origin/main)" = "<reviewed-main-sha>"
test "$(git rev-parse origin/chore/alternative-data-release-candidate)" = "<reviewed-release-sha>"
test "$(git rev-list --left-right --count origin/main...origin/chore/alternative-data-release-candidate)" = "0<tab><reviewed-ahead-count>"
test -z "$(git status --porcelain)"

gh pr create --base main --head chore/alternative-data-release-candidate --title "Release 0.1.0rc1" --body-file <reviewed-pr-body>
gh pr checks <pr-number> --watch --fail-fast
gh pr view <pr-number> --json reviewDecision,mergeStateStatus,statusCheckRollup
gh pr merge <pr-number> --merge --delete-branch=false

git fetch origin --prune --tags
git merge-base --is-ancestor <reviewed-release-sha> origin/main
test "$(git rev-parse origin/main^1)" = "<reviewed-main-sha>"
test "$(git rev-parse origin/main^2)" = "<reviewed-release-sha>"
gh run watch <post-merge-run-id> --exit-status

test -n "$(git config --get user.signingkey)"
test -z "$(git tag -l v0.1.0rc1)"
test -z "$(git ls-remote --tags origin refs/tags/v0.1.0rc1)"
git tag -s v0.1.0rc1 origin/main -m "FairLendKit 0.1.0rc1"
git tag -v v0.1.0rc1
test "$(git rev-list -n 1 v0.1.0rc1)" = "$(git rev-parse origin/main)"
git push origin refs/tags/v0.1.0rc1
gh release create v0.1.0rc1 --prerelease --verify-tag --title "FairLendKit 0.1.0rc1" --notes-file docs/releases/v0.1.0rc1.md
gh release view v0.1.0rc1 --json isPrerelease,tagName,targetCommitish,url
```

The PR number, merge SHA, both merge parents, CI run IDs, tag object ID,
release URL, signer type, signer fingerprint, and successful verification
output are appended to the final release evidence. This sequence does not
publish to PyPI and grants no data-access permission.
