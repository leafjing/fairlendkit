# FairLendKit 0.1.0rc1 release notes

Release type: GitHub prerelease. This release is not published to PyPI.

## Highlights

- Preserves the reviewed Milestone 3 audit engine and Milestone 4 installed CLI
  workflow with canonical JSON, CSV, and HTML reports.
- Adds strict alternative-data source, temporal-leakage, revision, reversal,
  coverage, and reason contracts (AD-0).
- Adds disclosure-controlled aggregate quality evidence with primary and
  complementary suppression and historical-release constraints (AD-1).
- Adds explicit cash-flow, rent, and utility adapters and deterministic typed
  signal profiles using Decimal amount semantics (AD-2).
- Adds disclosure-controlled credit-risk diagnostics with deterministic
  counter bootstrap, reliability gates, and complete trace evidence (AD-3).
- Adds potential proxy-risk screening with fixed development/holdout modeling,
  paired and stratified bootstrap evidence, typed flags, and canonical JSON,
  CSV, and HTML projections (AD-4).

## Scope and safety boundaries

This prerelease contains no real alternative-data dataset, admitted data
artifact, or live retrieval invocation. The separately reviewed retrieval
harness is not part of this release tree. This release does not authorize data
download, admission, promotion, repository storage, or redistribution.

Alternative-data outputs are screening and review evidence only. They do not
provide threshold recommendations, automated feature removal, model decisions,
or causal, discrimination, legal, or compliance conclusions.

## Tag signing and publication controls

The public tag is an annotated, SSH-signed tag created only from
the independently approved release commit after the merge and post-merge CI
gates pass. No unsigned-tag fallback is permitted. The release operator must
use an existing SSH signing identity that GitHub can verify for the project
maintainer account. Only the public-key fingerprint and verification result are
recorded; private-key material is never read, copied, logged, or included in
release evidence.

The preflight must prove that `gpg.format=ssh`, the configured signing key has
the independently reviewed fingerprint, the corresponding identity is
available to the signing process, and the approved allowed-signers file is
configured. It also proves that the tag does not exist locally or remotely and
that the approved release commit is an ancestor of the current `origin/main`.
Tag creation uses Git's forced signing mode (`git tag -s`) and is followed by
`git tag -v` plus an exact target check before the tag is pushed. GitHub Release
creation uses `--verify-tag` and targets the same immutable tag. If any SSH
preflight fails, the reviewed PR may still merge, but tag and prerelease
publication remain blocked until custice configures an eligible signing
identity.

Public tags are never moved or reused. A normal rollback is a revert PR against
the merge commit. If a published prerelease must be withdrawn, mark the GitHub
prerelease as withdrawn and publish a correcting version; do not delete or move
the public tag. Deleting a public tag or release requires separate emergency
authorization and a preserved incident record.

## Reviewed execution sequence

The values in angle brackets are filled from independently reviewed evidence;
no command runs if any exact comparison fails.

```bash
set -euo pipefail

: "${REVIEWED_MAIN_SHA:?set reviewed main SHA}"
: "${REVIEWED_RELEASE_SHA:?set reviewed release SHA}"
: "${REVIEWED_AHEAD_COUNT:?set reviewed ahead count}"
: "${REVIEWED_PR_BODY:?set reviewed PR body path}"
: "${REVIEWED_SSH_SIGNING_FINGERPRINT:?set reviewed SSH fingerprint}"
: "${REVIEWED_SSH_KEY_TYPE:?set reviewed SSH key type}"
: "${REVIEWED_SSH_SIGNING_PRINCIPAL:?set reviewed SSH principal}"

git fetch origin --prune --tags
test "$(git rev-parse origin/main)" = "$REVIEWED_MAIN_SHA"
test "$(git rev-parse origin/chore/alternative-data-release-candidate)" = "$REVIEWED_RELEASE_SHA"
test "$(git rev-list --left-right --count origin/main...origin/chore/alternative-data-release-candidate)" = "0"$'\t'"$REVIEWED_AHEAD_COUNT"
test -z "$(git status --porcelain)"

gh pr create --base main --head chore/alternative-data-release-candidate --title "Release 0.1.0rc1" --body-file "$REVIEWED_PR_BODY"
PR=$(gh pr list --base main --head chore/alternative-data-release-candidate --state open --json number --jq '.[0].number')
test -n "$PR"
PR_STATE=$(gh pr view "$PR" --json headRefOid,baseRefOid,reviewDecision,mergeStateStatus)
test "$(printf '%s' "$PR_STATE" | jq -r .headRefOid)" = "$REVIEWED_RELEASE_SHA"
test "$(printf '%s' "$PR_STATE" | jq -r .baseRefOid)" = "$REVIEWED_MAIN_SHA"
gh pr checks "$PR" --watch --fail-fast
PR_STATE=$(gh pr view "$PR" --json headRefOid,baseRefOid,reviewDecision,mergeStateStatus)
test "$(printf '%s' "$PR_STATE" | jq -r .headRefOid)" = "$REVIEWED_RELEASE_SHA"
test "$(printf '%s' "$PR_STATE" | jq -r .baseRefOid)" = "$REVIEWED_MAIN_SHA"
test "$(printf '%s' "$PR_STATE" | jq -r .reviewDecision)" = "APPROVED"
test "$(printf '%s' "$PR_STATE" | jq -r .mergeStateStatus)" = "CLEAN"
test "$(git rev-parse origin/main)" = "$REVIEWED_MAIN_SHA"
gh pr merge "$PR" --merge --delete-branch=false --match-head-commit "$REVIEWED_RELEASE_SHA"

git fetch origin --prune --tags
git merge-base --is-ancestor "$REVIEWED_RELEASE_SHA" origin/main
test "$(git rev-parse origin/main^1)" = "$REVIEWED_MAIN_SHA"
test "$(git rev-parse origin/main^2)" = "$REVIEWED_RELEASE_SHA"
MERGE_SHA=$(git rev-parse origin/main)
test "$(git rev-list --parents -n 1 "$MERGE_SHA" | awk '{print NF}')" = "3"
POST_MERGE_RUN=$(gh run list --branch main --commit "$MERGE_SHA" --event push --limit 1 --json databaseId --jq '.[0].databaseId')
test -n "$POST_MERGE_RUN"
gh run watch "$POST_MERGE_RUN" --exit-status

test "$(git config --get gpg.format)" = "ssh"
SIGNING_KEY=$(git config --get user.signingkey)
test -n "$SIGNING_KEY"
SIGNER_INFO=$(ssh-keygen -lf "$SIGNING_KEY")
SIGNER_FP=$(printf '%s' "$SIGNER_INFO" | awk '{print $2}')
SIGNER_TYPE=$(printf '%s' "$SIGNER_INFO" | awk '{gsub(/[()]/, "", $4); print $4}')
test "$SIGNER_FP" = "$REVIEWED_SSH_SIGNING_FINGERPRINT"
test "$SIGNER_TYPE" = "$REVIEWED_SSH_KEY_TYPE"
ssh-add -l | awk '{print $2}' | grep -Fx "$SIGNER_FP"
ALLOWED_SIGNERS=$(git config --get gpg.ssh.allowedSignersFile)
test -r "$ALLOWED_SIGNERS"
SIGNING_PRINCIPAL=$REVIEWED_SSH_SIGNING_PRINCIPAL
grep -Eq "^${SIGNING_PRINCIPAL}([,[:space:]])" "$ALLOWED_SIGNERS"
test -z "$(git tag -l v0.1.0rc1)"
test -z "$(git ls-remote --tags origin refs/tags/v0.1.0rc1)"
git tag -s v0.1.0rc1 "$MERGE_SHA" -m "FairLendKit 0.1.0rc1"
TAG_VERIFY=$(git tag -v v0.1.0rc1 2>&1)
printf '%s\n' "$TAG_VERIFY"
printf '%s' "$TAG_VERIFY" | grep -F "Good \"git\" signature for $SIGNING_PRINCIPAL"
test "$(git rev-list -n 1 v0.1.0rc1)" = "$MERGE_SHA"
git push origin refs/tags/v0.1.0rc1
gh release create v0.1.0rc1 --prerelease --verify-tag --title "FairLendKit 0.1.0rc1" --notes-file docs/releases/v0.1.0rc1.md
test "$(gh release view v0.1.0rc1 --json isPrerelease --jq .isPrerelease)" = "true"
test "$(gh release view v0.1.0rc1 --json tagName --jq .tagName)" = "v0.1.0rc1"
gh release view v0.1.0rc1 --json targetCommitish,url
```

The PR number, merge SHA, both merge parents, CI run IDs, tag object ID,

and GitHub verification
output are appended to the final release evidence. This sequence does not
