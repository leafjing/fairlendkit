# Core concepts

FairLendKit is a reproducible fair-lending audit toolkit for credit decisioning
systems. Its current core organizes audit evidence around six connected
concepts. These definitions describe implemented Milestone 3 behavior; future
roadmap capabilities are identified separately.

## Semantic validation

An audit is meaningful only when the data semantics are explicit. FairLendKit
requires configuration for the outcome, favorable label, score direction,
decision, favorable decision, audit group, and reference group. It distinguishes
an observed outcome from a model score and a lending decision instead of
guessing their meanings from column names or values.

See [Data specification](data-spec.md), [Canonical glossary](glossary.md), and
[Methodology and guardrails](methodology-and-guardrails.md).

## Fairness metrics and directed comparisons

The engine computes group-level selection and model-performance metrics and
preserves the direction of reference comparisons. Adverse impact ratio, for
example, is the comparison group's selection rate divided by the configured
reference group's selection rate. These are descriptive statistical measures,
not findings of causation, intent, fairness, or legal compliance.

See [Metric contracts](metric-contracts.md).

## Reliability states

Every metric is interpreted with its support. FairLendKit distinguishes
`reliable`, `unreliable`, `undefined`, and `not_applicable` outcomes using
documented metric-specific gates. A point estimate can be mathematically defined
while still lacking sufficient support for an unqualified interpretation.

See [Milestone 3 core audit engine](milestone-3-core-audit-engine.md) and
[Undefined reasons](undefined-reasons.md).

## Statistical uncertainty

Eligible metrics can carry deterministic bootstrap intervals generated by the
project's fixed SHA-256 counter procedure. An interval communicates sampling
variability under the documented method. It does not absorb measurement error,
selection bias, dataset shift, omitted-variable bias, or causal uncertainty.

See [Methodology and guardrails](methodology-and-guardrails.md).

## Risk flags

The current core can produce a reliability-gated adverse-impact-ratio screening
flag. A flag is a prompt for practitioner review. It is not an automated
fairness judgment, legal conclusion, or remediation recommendation.

## Reproducible reporting

`run_audit(data, config)` assembles a renderer-neutral Schema 2.0 result. Stable
metric keys, deterministic compact JSON serialization in the supported locked
environment, explicit migration from Schema 1.0, fixed examples, and byte-level
release oracles make the evidence traceable and reproducible. This is a project
serialization contract, not an independent JSON standard. HTML/CSV
renderers and a CLI are not currently implemented.

See [Report schema](report-schema.md) and
[Milestone 3 release evidence](milestone-3-release-evidence.md).
